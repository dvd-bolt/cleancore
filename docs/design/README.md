# Три прототипа дизайна CleanCore

Статус: варианты для выбора, **финальный дизайн не утверждён**. Подготовлено 2026-10-14. Это отдельное исследование оформления; приложение Tauri и модули мониторинга ещё не реализованы.

## Как посмотреть

Откройте [интерактивный прототип](index.html) в браузере. Вверху находятся три переключателя направления. Навигация внутри окна открывает обзор, процессы, очистку, журнал и настройки. Системные показатели намеренно отсутствуют: backend не подключён.

Прототип работает как локальный HTML, без установки зависимостей и внешних ресурсов. При просмотре через HTTP запустить из корня проекта:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Затем открыть `http://127.0.0.1:4173/docs/design/index.html`. Завершение сервера — Ctrl+C в соответствующей терминальной сессии.

## Направления

Для Studio дополнительно подготовлены [пять палитр](STUDIO_PALETTES.md) и [общая галерея сравнения](studio.html). Их можно переключать в исходном интерактивном прототипе. Финальная палитра ожидает выбора.

| 3 | Signal | Инструментальная панель; узкая навигация, большой график и вертикальная колонка показателей | Фон #111720, поверхность #1a2735, акцент #a2cce8 | 14 |

DFII — качественная внутренняя оценка направления: влияние 4 + соответствие продукту 5 + реализуемость 4 + производительность 4 − риск согласованности 3 = 14. Это дизайнерская оценка, не результат пользовательского исследования.

Визуальные якоря: у Control — мятная боковая навигация, у Studio — широкая янтарная композиция, у Signal — колонка инструментальных показателей с графиком слева. Во всех вариантах сохраняются доверие к данным, спокойная подача и явный контроль очистки.

## Общая система оформления

- Заголовки: локальный Bahnschrift, fallback Trebuchet MS; основной текст: Trebuchet MS с локальным fallback; числа: Cascadia Mono/Consolas.
- Файлы шрифтов Windows не копируются и не распространяются. На другой ОС возможен другой fallback.
- Цвета заданы CSS-переменными; у каждого направления один основной акцент.
- Ритм отступов — преимущественно 8/16/24/32 px; плотность и радиусы различаются по направлениям.
- Иконки и иллюстрация выполнены собственными SVG-примитивами, сторонние изображения не загружаются.
- Движение: краткие состояния hover/press; постоянных анимаций нет. Учитывается prefers-reduced-motion.
- Кнопки имеют видимый клавиатурный фокус; у узкой навигации сохранены доступные имена и подсказки.

## Что работает в прототипе

Переключение трёх концептов, пяти страниц, CPU/RAM/сети, состояния паузы, направления сортировки, поля поиска, выбора интервала и сообщения о неподключённом сканере. Эти элементы показывают поведение интерфейса; они не читают систему, не запускают задачи и не сохраняют настройки приложения.

## Проверки

- В браузере проверены все направления и страницы, переключатели, поиск, сортировка, настройки и безопасное сообщение очистки.
- При проверке консоли ошибок/предупреждений не обнаружено.
- Все три направления проверены при viewport 390 × 844: горизонтального переполнения страницы не обнаружено. Временный размер браузера сброшен.

- Rust/Tauri/frontend build неприменимы: продуктовый каркас ещё отсутствует. Полный аудит контраста и экранных дикторов предстоит при реализации.

## На каком этапе делать дизайн

Сейчас выбирается направление. После выбора зафиксировать название, палитру, типографику, расположение блоков и компоненты в отдельном принятом решении. Пока такого решения нет.

- **Этап 1, модуль 1.3:** перенос утверждённой композиции в React, навигация и страницы.
- **Этап 1, модуль 1.4:** реализация компонентов и дизайн-токенов выбранного направления.
- **Этап 1, модуль 1.5:** загрузка, ошибки, пустые данные, разрешения и доступность состояний.
- **Этап 2:** подключение реальных метрик и процессов, проверка таблиц и графиков на настоящих данных.
- **Этапы 3–6:** новые экраны в той же системе оформления.
- **Этап 7, модуль 7.4:** итоговая проверка доступности и масштабирования Windows.

Создание этих макетов не закрывает модули 1.3/1.4: они требуют работающего приложения.
