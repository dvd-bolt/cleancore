Текущие результаты этапов 1–7 — в [отчёте](reports/STAGES1_7.md). Наличие тестов не закрывает критерии чистой установки, Корзины и совместимости; обязательная матрица — в [RELEASE](RELEASE.md).

## Команды после создания каркаса

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
pnpm lint
pnpm typecheck
pnpm test --run
pnpm build
```

При создании frontend добавить именно эти scripts. Примеры не подтверждают их существование сегодня. На чистом окружении после появления lockfile использовать `pnpm install --frozen-lockfile`.

В CI также добавить аудит уязвимостей и лицензий Rust/frontend с закреплёнными инструментами. Не включать YAML, который притворяется рабочим до появления проекта.

## Реальные Windows-тесты

Проверки junctions, sharing modes и Windows API выполнять на Windows. Синхронизировать race-тесты контролируемыми точками выполнения, а не только случайными задержками. Все тестовые цели создаются в отдельном каталоге. Если создание symlink недоступно без специальных настроек, записать skip и причину; не повышать права всей программы.

Большие деревья обрабатывать без полной загрузки в память. Фактические пределы ресурсов и результаты измерений фиксировать в отчёте, не выдумывать значения.

## Документы

- Все локальные Markdown-ссылки должны вести к существующему файлу/разделу.
- IDs задач уникальны, зависимости существуют и не образуют циклы.
- Таблицы и кодовые блоки корректны; файлы в UTF-8 с завершающим переводом строки.
- Не должно быть заявления о готовом приложении, публикации или пройденных продуктовых тестах.

## Отчёт

Использовать [REPORT](templates/REPORT.md). Для каждой команды записывать выходной код и существенный результат. «Не запущено», «неприменимо», «пропущено» и «пройдено» — разные состояния.

## Дополнение этапа 8

Проверки cleaner-assistant: ограниченный парсер GGUF; согласие для конкретной модели;
контекст ID/TTL; отсутствие ответа без модели/runtime; одноcтрочный private stdin;
фиксированные offline аргументы; bounded output. IPC проверяет local-main ACL и
запрет дополнительных полей контекста. Frontend проверяет отключённое состояние,
честные null, экранирование данных и типизированные вызовы.

Отдельно после provisioning запускается ignored native-runtime fixture с повреждёнными
весами. Для приёмки остаются настоящий лицензированный GGUF, русский ответ по метрикам,
ошибкам и скану; отмена/отключение во время длинного ответа; замеры RAM/CPU и отсутствие
сети на Windows 10/11. Без этих свидетельств весь этап не отмечается принятым.

## Исправления 2026-10-15

Новые Windows fixture проверяют частичный отчёт с занятым каталогом/пределом глубины,
эксклюзивное удаление выбранного собственного файла, запрет подмены файла/родителя,
пропуск занятого и изменённого, сквозные intent/confirmation/result в SQLite.
HKCU StartupApproved проверяется только на собственном тестовом ключе, пользовательские
записи не переключаются автоматическими тестами. Фактический запуск при следующем входе
в Windows не проверялся. [Отчёт](reports/FIXES_2026_10_15.md).
