# Объединение этапов 3 и 4

Дата: 2026-10-14. Разработка параллельная, включение очистки — после общей приёмки.

## Где находится результат

Ветка `codex/stage4-execution`, worktree `C:/Users/dvd/.codex/worktrees/stage4-execution/clean`.

Первый коммит ветки фиксирует ранее существовавшую рабочую папку, включая незавершённый сканер другой нейронки. Он не означает реализации этапа 3 этим исполнителем. Коммит этапа 4 следует отдельно; переносить его поверх завершённого этапа 3, разрешая конфликты общих точек композиции.

## Границы файлов

- Этап 3: `crates/cleaner-cleanup`, каталог правил, root validation, scanner/tasks и UI анализа.
- Этап 4: `crates/cleaner-execution`, `cleaner-core/src/cleanup.rs`, `cleaner-storage/src/audit.rs`, `src-tauri/src/cleanup_commands.rs`, `src/features/cleanup-execution`.
- Общие точки объединения: Cargo manifests/lock, `state.rs`, `lib.rs`, `build.rs`, capabilities, `CleanupPage`, `JournalPage`, документация.

Не заменять общий файл целиком из одной ветки. Сохранить обе группы команд и capabilities. У execution-preview отдельная команда `get_execution_preview`: существующий порционный `get_cleanup_preview` этапа 3 сохраняется.

## Обязательный контракт снимка

Текущий StoredPreview этапа 3 содержит пути/размеры, но не доказанную идентичность на момент сканирования. Автоматическая конверсия в разрешение исполнения запрещена.

1. Сканер устанавливает разрешённый backend-корень `user-temp-v1`, его версию, отсутствие опасных перенаправлений и ограничения файловой системы. Frontend корень не задаёт.
2. Во время scan для каждого кандидата вызвать Rust-only `cleaner_execution::native::capture_candidate(root, relative)` и сохранить возвращённый `TrustedCandidate`. Отказ — исключение с причиной. Не захватывать идентичность задним числом после показа старого preview.
3. По завершении scan передать неизменяемый набор в `state.cleanup.publish_preview(objects)`; execution DTO получают собственные UUID object ID. UI должен показывать именно этот снимок. Частично/отменённые scan не публиковать как полные результаты.
4. Предел текущего execution-preview — 1000 кандидатов, 8 активных снимков, TTL 10 минут. Для больших списков требуется согласованное расширение пагинации; нельзя незаметно обрезать выбор.
5. Выбор изначально пуст. `prepare_cleanup_confirmation` принимает только preview ID и object IDs. Подтверждение живёт до 120 секунд; новый выбор аннулирует прежний токен.
6. `start_confirmed_cleanup` принимает токен и явное подтверждение, сохраняет намерения до worker и возвращает operation ID сразу. UI опрашивает `get_cleanup_operation` и может вызвать `cancel_cleanup`.

Публикация TrustedCandidate — внутренняя интеграционная граница доверенного Rust-кода. Она не заменяет проверку разрешённого корня в сканере и не доступна через IPC. Типы `models::CleanupCandidate` этапа 3 и `cleanup::CleanupCandidate` этапа 4 пока разделены; согласовать единый внешний DTO при интеграции, без смешения ID старого и нового preview.

## Корзина и условия допуска

Production `DisabledRecycle.available()` возвращает false. Read-only `revalidate` не даёт полномочия на последующее удаление по пути: её дескрипторы закрываются после проверки. Нет окончательного удаления, смены ACL, elevation или shell.

До реализации активного ObjectAction нужно доказать непрерывную привязку цели и родителей при самой операции Корзины, отсутствие fallback на окончательное удаление, корректную обработку sharing modes/memory mappings и поддерживаемой файловой системы. Проверить junction/reparse/file/parent swap между последней проверкой и действием, ACL, занятость, исчезновение, отказ Корзины и журнала. Размер/mtime и read-only проверка сами по себе race не устраняют.

Адаптер должен возвращать Recycled только после подтверждённого результата Корзины. Неподтверждённый исход — Unknown и остановка дальнейших действий. Ошибка SQLite до действия запрещает запуск; ошибка результата останавливает пакет и не обещает автоматическое восстановление.

## Проверки перед объединением

Пройти [TESTING](TESTING.md), [SECURITY](SECURITY.md), [THREAT_MODEL](THREAT_MODEL.md). Запустить fmt/clippy/test, frontend lint/test/build, документацию; затем native smoke-test общего сценария. Нынешние тесты lifecycle используют тестовый адаптер без изменения пользовательских файлов. Они не подтверждают работоспособность настоящей Корзины.

Историю читать порциями, не очищать автоматически. Восстановление журнала не повторяет операции. Файл `.cleanup.lock` удерживается Windows share_mode(0) на время жизни StorageManager; второй владелец не может пометить живую операцию прерванной. Если постоянное хранилище недоступно, исполнение блокируется.
