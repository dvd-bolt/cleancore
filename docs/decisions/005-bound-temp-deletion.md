# Решение 005 — явная безвозвратная очистка временных файлов

Дата: 2026-10-15. Статус: принято для локального кандидата по запросу пользователя.

## Контекст

Реальное исполнение было выключено: Windows Shell Корзина принимает путь, а удержание
проверенного read handle не разрешает безопасно передать действие этому пути.
Пользователь запросил работающую очистку. ТЗ требует Корзину по возможности, не
требуя небезопасного fallback.

## Решение

Добавлен отдельный явно названный режим безвозвратного удаления, без попытки сначала
вызвать Корзину. Только user-temp-v1, выбранные ID из backend snapshot, возраст от
7 суток. Список и предупреждение показываются до отдельного checkbox и финальной
кнопки «Удалить выбранное безвозвратно». Журнал намерений обязателен.

BoundDelete открывает проверенных родителей с запретом write/delete; последний файл
открывает с GENERIC_READ/DELETE и share=0. Проверяет identity/метаданные/родителей,
reparse/type/link-count, затем вызывает SetFileInformationByHandle(FileDispositionInfo)
на этом же удерживаемом handle. Не вызывает DeleteFile(path), shell или повышение прав.
Отказ открытия/проверки/удаления — пропуск; неизвестный исход/сбой журнала останавливает
пакет. Существующие Recycled outcomes остаются совместимы; новый статус Deleted и
deleted_bytes не выдаются за Корзину или измеренное освобождение пространства.

Неполный scan из-за недоступной подпапки сохраняет проверенный immutable subset.
Его можно выбрать только после отдельного согласия с неполнотой. Отмена, fatal root
failure и любые ресурсные лимиты не публикуют execution-preview. Это заменяет прежний
запрет всех Partial: неполнота обзора не означает подмену уже захваченных идентичностей.
Непроверенные объекты в исполнение не добавляются.

## Альтернативы

| Вариант | Достоинство | Ограничение | Решение |
| --- | --- | --- | --- |
| Корзина по пути после закрытия handles | Восстановление | Подмена объекта в разрыве | Не включать |
| Перемещение в карантин | Возможность восстановления | Не освобождает место; другая семантика | Отложено |
| Удаление через проверенный handle | Операция привязана к объекту | Безвозвратно | Выбрано с явным подтверждением |

## Проверки и последствия

Windows fixtures: удаляется только собственный выбранный старый файл; changed/busy/
hardlink пропускаются; замена файла и переименование родителя между проверкой и
disposition не удаются. Сквозной scan/confirm/execute/SQLite fixture проверяет согласие,
изменение после preview и результат журнала. Не выполнялись действия над файлами
пользователя, ACL/mapped/junction matrix и приёмка Windows 10 остаются открыты.

Источник API: [Microsoft SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle).
Решение не объявляет безопасную Корзину реализованной и не закрывает release gate.
