# Решение 004 — локальный помощник без полномочий исполнения

Дата: 2026-10-14. Статус: принято для кандидата, приёмка с весами открыта.

## Контекст

Этап 8 требует локальных объяснений и ручного управления моделью. Облако, автономные
действия и обязательная модель противоречат ТЗ. Выпуск 7.6 остаётся заблокирован;
по прямому запросу пользователя реализация 8 выполняется в непубликуемом кандидате.

## Решение

Собственный cleaner-assistant запускает закреплённый llama-completion CPU отдельным
процессом с фиксированными аргументами, --offline и очищенным окружением. Сервер,
RPC и shell не запускаются. Сводка и вопрос передаются одной UTF-8 строкой stdin,
не через аргументы и не через файл. Ответ — обычный текст без HTML и исполняемых ссылок.
Навигация вычисляется типизированными правилами backend и только открывает штатную страницу.

GGUF выбирается системным диалогом. Backend удерживает файл и родителей через
BoundReader; запрещены ссылки, hardlinks и сетевые пути. Проверяются версия GGUF,
лимиты метаданных, размер 1 КБ–2 ГБ и список архитектур. Это предварительная проверка,
а не полная валидация тензоров или обещание качества модели. Лицензия в заголовке
не доказывает права: пользователь указывает источник условий и подтверждает их для
конкретного ID модели. Веса не поставляются и не скачиваются автоматически.

Один запрос, контекст 2048 токенов, генерация до 256 токенов, 2 CPU-потока,
90 секунд, stdout/stderr до 32 КБ каждый. Windows Job ограничивает память процесса
4 ГБ и число процессов одним, закрытие Job завершает дочерний процесс. Job назначается
сразу после spawn; это ограничение ресурсов, а не AppContainer или полноценная песочница.
Повреждённые веса всё равно обрабатывает нативный парсер: использовать доверенные модели.

## Альтернативы

| Вариант | Преимущества | Ограничения | Решение |
| --- | --- | --- | --- |
| Встроить llama.cpp в Tauri | Меньше IPC | Сбой парсера/памяти затрагивает приложение | Отказ |
| HTTP server localhost | Готовый API | Слушающий endpoint и отдельная поверхность доступа | Отказ |
| Одноразовый CPU completion | Нет endpoint, процесс освобождается после ответа | Повторная загрузка весов, время запуска | Выбран |

## Последствия

Помощник выключен по умолчанию; выбор, лицензия и ответы действуют только в сессии.
Отключение отменяет запрос и отпускает модель после остановки worker. Основные страницы
не зависят от runtime и весов. ОС или локальный отладчик всё ещё могут читать память
обычного пользовательского процесса; полной изоляции от текущего пользователя нет.

Runtime: [llama.cpp b11429](https://github.com/ggml-org/llama.cpp/releases/tag/b11429),
commit d81235049384534c167caea52b85a694f6103d14, MIT; лицензия LLVM OpenMP сохранена
отдельно. Исходники runtime не копировались и бинарники не менялись. Контрольные суммы
файлов закреплены в crates/cleaner-assistant/runtime-manifest.json.

## Проверка

Метаданные, привязка лицензии/контекста, лимиты, ACL и отсутствие модели проверяются
автоматически. Реальный закреплённый процесс проверен на отказе повреждённых весов.
Русский ответ, отмена во время инференса, память и совместимость на Windows 10/11
требуют настоящего GGUF и отдельной приёмки. [Отчёт](../reports/STAGE8.md).
