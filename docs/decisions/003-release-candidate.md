# Решение 003 — кандидат выпуска и границы готовности

Дата: 2026-10-14. Статус: принято для текущей проверки.

## Контекст

Запрос пользователя расширяет прежнее назначение этапа 5 до аудита и исправления этапов 1–7.
Этап 8 вне задания. Исходная рабочая копия была чистой; чужие изменения не сбрасывались.
Полная приёмка очистки требует доказанной связи проверенного объекта с операцией Корзины.
Текущий DisabledRecycle не предоставляет такой операции. Наличие сборки не доказывает совместимость с VM.

## Решение

Исправлять модули 1–7 последовательно, сохранять безопасный запрет удаления,
готовить NSIS-кандидат с офлайн WebView2, локальными данными и notices.
Реестр приёмки отделён от наличия реализации; scripts/check_release.py отвергает выпуск
до появления свидетельств по всем обязательным сценариям. Версию 1.0 не назначать заранее.

## Альтернативы

| Вариант | Последствия | Решение |
| --- | --- | --- |
| Закрыть проверочные handles и вызвать Корзину по строке пути | Снова возникает окно подмены объекта | Отклонён |
| Заменить Корзину окончательным удалением | Противоречит ТЗ и модели безопасности | Отклонён |
| Сохранить блокировку и явно показать открытые критерии | Часть задания остаётся незавершённой, данные защищены | Принят |

## Последствия

Реальное удаление и продуктовый выпуск остаются заблокированы. Разрешён read-only BoundReader,
который удерживает проверенные Windows handles файла и родителей при хешировании.
cleaner-disk использует его из cleaner-execution без циклической зависимости.
Radix Dialog 1.1.15 (MIT) подключён для фокуса, модальности и Escape; новая системная
зависимость не требуется: диалог сохранения использует Windows common dialogs через windows-sys.
Экспорт создаёт новый CSV-файл, выбор пути принадлежит системному диалогу.
