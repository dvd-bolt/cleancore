# Решение 006 — запуск с повышенными правами и анализ NTFS MFT

Дата: 2026-10-15. Статус: принято по прямому запросу пользователя; нативная приёмка отдельно от реализации.

## Контекст

Пользователь прямо потребовал запуск всего CleanCore от администратора и новый Rust-движок анализа по аналогии с WizTree. Это заменяет прежнее ограничение обычных прав основного процесса в ТЗ/AGENTS. Остальные ограничения очистки сохраняются. Предложение отдельного повышенного процесса пользователь отклонил.

## Решение

Windows manifest приложения задаёт requireAdministrator, uiAccess=false. Windows показывает UAC при запуске; приложение не обходит запрос и не меняет настройки UAC. Учетные данные другого администратора означают его профиль и настройки, это требует отдельной проверки.

Для обычного корня X:\ используется raw volume handle с GENERIC_READ и sharing read/write/delete. Никаких операций записи, блокировки/размонтирования тома, драйвера или shell-команд. FSCTL_GET_NTFS_VOLUME_DATA задаёт геометрию; собственный Rust-парсер читает MFT блоками по 4 MiB. Разбираются fixup с шагом 512, resident/nonresident атрибуты, signed data runs, расширения runlist самого $MFT через attribute list, версия NTFS 3.0/3.1, базовые/расширенные записи и sequence numbers родителей.

Индекс агрегируется снизу вверх и хранится в памяти для просмотра подпапок. Один том/индекс; явный повторный анализ корня перечитывает данные. Оценочный бюджет записей 1 GiB и потолок 4 млн активных записей дают явный partial при достижении; это не обещание жёсткого RSS лимита. Снимок работающего тома не атомарен. Ошибочные и недостижимые записи дают диагностику.

Основной размер — unnamed DATA; resident allocation=0, compressed/sparse allocation берётся из TotalAllocated. Hard links учитываются один раз с детерминированным выбором имени/папки. Это правило отличается от подсчёта всех имён. Named streams не включаются и показываются в предупреждениях. Сумма allocated не обязана совпадать с занятым местом Windows. Системный $MFT, как DATA системного файла, может входить в сумму; часть остальных служебных структур не представлена обычными DATA.

При ошибке bootstrap MFT обычный обход остаётся доступен, с явной причиной fallback. Для отдельных папок без готового индекса и других файловых систем используется прежний обход с его ограничениями; это не fast MFT. Дубликаты по содержимому остаются отдельным сканером.

## Последствия

Весь основной процесс, WebView2 и дочерние процессы теперь получают повышенный контекст. Это расширяет последствия ошибок IPC/парсеров и не является sandbox. Ограничения Job у локального помощника не снимают права администратора. Его реальная модель пока не выбрана и нативная приёмка остаётся открытой. Universal shell/helper API не добавляется. Повышение прав не расширяет категории очистки и не заменяет scan/preview/confirm/recheck/journal.

Установка/подмена бинарников рядом с повышенным приложением — отдельный риск: release-приёмка должна проверить защищённое размещение приложения и ресурсов. Текущий exe в рабочем каталоге является локальной сборкой, не принятым способом защищённого распространения.

## Источники и заимствование

Реализация собственная, код WizTree/других сканеров не копировался; новых сторонних crates нет. Используется уже закреплённый windows-sys 0.59.0 (MIT/Apache-2.0). Источники формата: [Microsoft MFT](https://learn.microsoft.com/en-us/windows/win32/devnotes/master-file-table), [attributes](https://learn.microsoft.com/en-us/windows/win32/devnotes/attribute-record-header), [fixup](https://learn.microsoft.com/en-us/windows/win32/devnotes/multi-sector-header), [volume data](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-fsctl_get_ntfs_volume_data). Документация сверена 2026-10-15.

## Проверки

Таргетированные parser/tree regression tests и malformed/truncation cases; UI navigation без нового scan; Clippy, frontend lint/build; embedded manifest inspection. Native MFT на реальном томе и сравнение с WizTree фиксируются отдельно в отчёте. Синтетические тесты не доказывают скорость/полноту реального диска.
