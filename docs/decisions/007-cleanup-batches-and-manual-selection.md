# Решение 007 — партии очистки и ручной выбор на карте

Дата: 2026-10-15. Статус: принято для локального кандидата 0.0.4 по запросу внедрить [план](../CLEANER_IMPLEMENTATION_PLAN.md). Нативная приёмка Windows 10/11 остаётся отдельным критерием.

## Контекст

Пользователь запросил новые категории, работающую очистку и удаление из карты. Ранее публикация execution-preview ограничивалась user-temp-v1 и полным обходом до 1000 кандидатов. Это превращало лимит в тупик на большом Temp. Решение 005 гарантировало привязку безвозвратной операции к удерживаемому объекту; безопасная Корзина не была допущена.

## Решение

- Сканер хранит ReadDir-курсор и идентичности каталогов на backend, освобождает DirectoryLease между порциями и проверяет всю цепочку перед продолжением.
- До 1000 кандидатов образуют отдельную подтверждаемую партию. Это граница содержимого, а не разрешение исполнять произвольный ресурсно прерванный снимок. Непрерывный отрезок ограничен 2 секундами/50 000 записями, глубина — 32.
- TIME_LIMIT/ENTRY_LIMIT задают внутренние порции: при наличии прогресса worker автоматически продолжает их; сами по себе они не разрешают исполнение. Конфигурация без прогресса остаётся остановленной и не зацикливается. DEPTH_LIMIT и отмена не разрешают его. Уже захваченная готовая партия допускается после отдельного согласия с неполнотой; наличие других опасных диагностик запрещает публикацию по тем же проверкам.
- Переход к следующей партии отзывает прежний preview и подтверждения. При активном исполнении переход отклоняется. Невыбранные файлы остаются; новый полный анализ снова их обнаружит.
- Каталог расширен фиксированными собственными правилами. UI не задаёт корни обычных категорий. Для проектов разрешён только выбранный вложенный проект в Desktop/Documents/Downloads с проверенным Cargo.toml/package.json и фиксированным target/node_modules.
- Новый профиль исполнения задаёт категорию и минимальный возраст на backend. Возраст повторно проверяет BoundDelete на том же объекте. Кеш браузера дополнительно проверяет отсутствие процесса перед анализом и действием; это не блокировка запуска браузера на всё время задачи.
- Ручное удаление из карты ограничено Desktop/Documents/Downloads/Music/Pictures/Videos текущей учётной записи. Backend получает report ID и MFT reference, сверяет свежий file reference, строит новый список. Корни этих папок, ссылки и виртуальные диски не допускаются.
- Небольшая папка: до 1000 объектов/32 уровней, свежий immutable список, потомки раньше родителей; Windows удаляет каталог только если он пуст. Новый потомок после preview остаётся и блокирует удаление родителя. Непроверяемая папка не публикуется частично.
- Дубликаты: пользователь явно задаёт оригинал и копии. Перед каждым удалением обе копии хешируются под удерживаемыми дескрипторами; сохраняемый объект удерживается до завершения действия. Кеш анализа не является разрешением удаления.
- Исключения и защищённые оригиналы проверяет общий адаптер исполнения. Изменение настроек отзывает подтверждения; повреждённые настройки блокируют действия. SQLite сохраняет параметры локально.

- Возможные остатки приложения первоначально только read-only: LocalAppData/Roaming, объяснение совпадения, состояние регистрации и неполнота. Общие папки издателя не объявляются остатками целиком. Контекст после запуска штатного удаления ограничен 30 минутами и не содержит сохранённых команд запуска.

## Корзина и приватность

Корзина остаётся недопущенной: вызов SHFileOperation/IFileOperation по имени не доказал атомарной привязки к захваченному объекту. Закрыть эксклюзивный handle и затем вызвать Shell по пути — неприемлемая замена проверенного исполнителя. Отказ не вызывает fallback. В UI прямо назван безвозвратный режим; Проводник доступен отдельным действием.

SQL-изменения истории/cookies не включены. SQLite WIN32_GET_HANDLE даёт возможный путь проверки основного файла, но не доказывает безопасное обращение со всеми journal/WAL/SHM при повышенных правах. Нужны отдельные реализация, резервирование и отрицательные тесты. Cookie DB и профиль целиком обычным файловым правилом не удаляются.

## Проверки и последствия

Фикстуры подтверждают продолжение, отзыв старых токенов, замену каталога в паузе, набор 1205 кандидатов, неизменность нового потомка, защиту оригинала и исключений. Результаты, сборка и ограничения — в [отчёте](../reports/CLEANER_EXPANSION_2026_10_15.md). Изменения не означают завершения всего плана и не закрывают release gate.
