# 008. Единый выбор после общего анализа

Дата: 2026-10-16. Статус: принято для локального кандидата.

## Причина

Сводка общего анализа не сохраняла исполнимый список: следующая партия отзывала
предыдущий preview. Повторный анализ каждой категории не давал пользователю общего
выбора и кнопки очистки. Простое сложение итогов также учитывало пересечения.

## Решение

TaskManager сохраняет захваченные сканером TrustedCandidate для текущей партии.
До продолжения её можно перенести в один GeneralManager. IPC принимает ID сессии
и задачи, не пути. Категории только для анализа и выбранного проекта не допускаются.
В общий список попадают лишь партии, допустимые по существующему execution_subset_allowed.
Дубликаты отсекаются по полному номеру тома и 128-битному FILE_ID_INFO. Сохраняется
первая допустимая принадлежность категории; сомнительный объект пропускается.

Список ограничен 50 000 объектами и 30 минутами. ID партии делает перенос идемпотентным.
После завершения список неизменяем. Ошибочные категории исключаются, при глубинном
лимите уже накопленные объекты этой категории отзываются. Отменённый общий анализ
не разрешает исполнение. Для неполной/ограниченной сводки требуется отдельное согласие.

Выбор задаётся только известными object_id. Backend формирует точное подтверждение
на 120 секунд; begin требует acknowledged=true и однократно потребляет его. Изменение
выбора требует нового подтверждения. При исполнении объекты делятся по исходным
категориям на партии до 1000. Внутренние preview/confirmation создаются только для
объектов подтверждённого общего выбора, с прежними возрастом и process guard.
Намерения каждой партии фиксируются до действий; результаты — после каждого объекта.
Постоянный журнал остаётся обязательным. Это не новое разрешение произвольного удаления.

Отмена действует на текущую партию и все последующие. Unknown, ошибка журнала,
исключение исполнителя или невозможность начать партию прерывают весь оставшийся
список без повторов. Общий прогресс живёт в памяти; каждая начатая партия имеет
собственную запись в постоянном журнале. После перезапуска нет автоматического
продолжения удаления. Незавершённые журнальные операции восстанавливаются прежним механизмом.

## Последствия

Frontend получает компактный индекс ID/категорий/размеров, пути читает страницами
до 100 (UI — 50). Подтверждение показывает только выбранные файлы, без рендера
всего большого списка сразу. Изменённые, занятые, исключённые и небезопасные объекты
пропускаются прежним исполнителем. На уровне одного действия сохраняются проверки
объекта/родителей, возраста, браузера и актуальных пользовательских исключений.

Показанный объём — логические размеры уникальных файлов, не обещание такого же
прироста свободного места. Корзина не добавлена: удаление безвозвратное, это указано
до финального согласия. Мастер-операция не сохраняется как отдельная таблица: её
начатые партии и ошибки доступны в существующем журнале.
