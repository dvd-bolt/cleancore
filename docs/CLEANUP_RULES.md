# Правила очистки

Статус: первая категория реализована и связана с подтверждением и журналом. Реальная операция Корзины заблокирована; полная приёмка исполнителя не завершена.

## Категория user-temp-v1

| Параметр | Правило |
| --- | --- |
| Источник | Временный каталог текущего пользователя, определяемый и проверяемый backend |
| Цели | Только обычные файлы поддерживаемой локальной файловой системы |
| Возраст | Не менее 7 суток после последнего изменения |
| Обход | Постепенный, с отменой, ограничениями глубины/объёма и безопасным пропуском при достижении лимита |
| Исключения | Symlinks, junctions, reparse points, hard links, недоступные или неопределённые объекты |
| Запрещённые цели | Системные каталоги, документы пользователя, сетевые/device-пути и альтернативные потоки |
| Действие этапа 3 | Только scan и preview; найденные объекты не меняются |
| Действие этапа 4 | Корзина только при доказанной безопасности конкретной операции |
| При отказе | Пропуск с причиной; окончательное удаление не подставляется |

Пределы: глубина 8, 50 000 записей каталогов, 1000 кандидатов, 60 секунд. Достижение лимита отображается как Partial и запрещает публикацию execution-preview. Корень берётся через Windows Known Folder LocalAppData/Temp; TEMP и LOCALAPPDATA из окружения не используются как источник доверия. На время перечисления удерживаются handle родителей без разрешения изменения/удаления. Если корень недоступен или перенаправлен, категория недоступна с объяснением. Это защита анализа, а не доказательство безопасной операции Корзины.

## Preview

Каждый результат связан с категорией, версией правила, временем и объектами, идентифицированными backend. Отображать путь, размер, причину включения и ограничения. Размер кандидатов не обещает немедленного освобождения места.

Выбор изначально пустой; пользователь выбирает объекты явно. Смена набора, правила или цели не скрывается за старым подтверждением. Frontend не добавляет новые пути через запрос исполнения.

## Проверка перед исполнением

Повторно проверить корень, компоненты пути, тип, идентичность, изменения метаданных и доступность. Размер и время сами по себе не являются надёжной идентичностью. Учесть race между повторной проверкой и операцией.

Способ проверки занятости должен учитывать Windows sharing modes; сам факт, что ОС позволяет удаление, не доказывает отсутствие использования файла. Не менять ACL/атрибуты, не завершать процессы и не назначать удаление после перезагрузки.

## Журнал и отмена

1. До действия сохранить намерение. Если запись не удалась, действие не начинать.
2. Выполнить только допустимую операцию.
3. Сохранить исход: обработан, пропущен, ошибка или неизвестный результат.
4. При отмене остановить дальнейшие объекты и показать уже выполненное.
5. После аварии не повторять незавершённую операцию автоматически.

SQLite и файловая система не образуют одну транзакцию. Корзина не гарантирует восстановление всех объектов и не равна окончательному освобождению пространства.

## Расширение каталога

Каждая категория получает собственный ID, версию, источники, исключения, описание последствий и тесты. Каталоги сторонних программ и правила BleachBit не подключаются автоматически. Поиск дубликатов не даёт разрешения удалить пользовательские документы.

Связанные документы: [модель угроз](THREAT_MODEL.md), [API](API_CONTRACTS.md), [проверки](TESTING.md).

## Категория 8.6: старые журналы Temp

user-temp-logs-v1: только обычные .log (без учёта регистра) внутри доверенного
пользовательского Temp, возраст не менее 30 суток. Остальные исключения, удержание
родителей, лимиты и Partial такие же, как у исходной категории. Не анализирует
содержимое логов и не обходит каталоги приложений вне Temp.

Это отдельная категория просмотра. Она не публикует execution-preview и не даёт
разрешения на удаление: до безопасного адаптера Корзины 4.3 расширение не включает
новые деструктивные действия. Fixture проверяет старый LOG, свежий log и старый txt.

## Безвозвратный режим 2026-10-15

Для user-temp-v1 включён явно подтверждаемый BoundDelete. Он не отправляет в Корзину.
Предупреждение, irreversible checkbox, точный выбранный список, SQLite intent и повторная
проверка обязательны. Исход Deleted учитывается отдельно от Recycled. [Решение 005](decisions/005-bound-temp-deletion.md).
Partial с недоступными подпапками допускает только захваченный проверенный subset
после дополнительного согласия; отмена/fatal/ресурсные лимиты запрещают исполнение.
Это уточнение заменяет предыдущий общий запрет всех Partial.


## Расширение 0.0.4

[Решение 007](decisions/007-cleanup-batches-and-manual-selection.md) расширяет прежний ограниченный режим. Каталог: Temp 7 дней; logs Temp 30 дней только анализ; Chrome/Edge/Firefox caches 7; DirectX 7; CrashDumps .dmp 30; Windows Temp 7; WER 30; target/node_modules выбранного проверенного проекта 7. Каждый пункт имеет собственную границу; общих sweep по расширениям диска нет.

Кеш браузера не включает cookies/историю/Local Storage/IndexedDB; активный процесс блокирует категорию. Ссылки/hard links/занятые файлы пропускаются, что может ограничить очистку pnpm. Обычные категории используют Known Folders; проекты — только вложенные Desktop/Documents/Downloads с манифестом и фиксированным дочерним кешем.

До 1000 файлов — подтверждаемая партия с сохранённым курсором. TIME/ENTRY порции продолжаются автоматически при прогрессе; их прерывание само по себе не разрешает исполнение. DEPTH_LIMIT, отмена и fatal блокируют. Переход к следующей партии отзывает прежние разрешения. При неполном обзоре необходимо отдельное согласие; объекты перепроверяются перед действием.

Ручной выбор карты не объявляется мусором: отдельный профиль user-files-v1, ограниченные пользовательские Known Folders, свежий список, безвозвратное предупреждение. Непустая папка не удаляется; новые дети не подхватываются. Дубликаты используют duplicates-v1 и удерживаемый оригинал с повторным SHA-256. Исключения обязательны для всех действий.

Корзина и категории изменения приватных баз остаются недопущенными. [Фактические проверки](reports/CLEANER_EXPANSION_2026_10_15.md).
