# История изменений

## 2026-10-14 — компоненты этапа 4 в отдельной ветке

Добавлены immutable preview/confirmation lifecycle, одноразовые токены, запись намерений и per-object результатов в SQLite, восстановление после перезапуска, отмена, narrow IPC, UI подтверждения и итогов. Полная приёмка этапа 4 не объявляется завершённой.

Исправлены обработка ошибок IPC, CSP и разрешения команд, первые замеры сети/процессов, разрывы и временная шкала графика, атомарность настроек и жизненный цикл запросов UI. Заглушки явно обозначают будущие функции. Полная приёмка этапов пока не закрыта; результаты и ограничения — в [отчёте](walkthrough.md).

### 2026-10-14 — v0.2.0 (Этап 5: Анализ диска и дубликатов)

- Создан крейт `cleaner-disk`:
  - Модуль 5.1: Отменяемый потоковый обход файловой системы `analyze_directory_tree` с поддержкой `AtomicBool`, пропуском reparse points/junctions/symlinks и безопасной обработкой ошибок доступа.
  - Модуль 5.2: Определение размеров и сортировка крупнейших потребителей дискового пространства (`largest_files`, `largest_dirs`) с вычислением процентной доли от каталога.
  - Модуль 5.3: Категоризация по 7 классам (`Videos`, `Images`, `Documents`, `Archives`, `Audio`, `Code`, `Other`) и построение карты распределения.
  - Модуль 5.4: Трёхфазный алгоритм поиска дубликатов (Czkawka 3-phase logic: размер -> prehash 16 КБ -> полный SHA-256). Детектирование Windows Hard links через `GetFileInformationByHandle` с исключением из дубликатов. Защита от TOCTOU. Режим инспекции (автоудаление отключено).
  - Модуль 5.5: Потокобезопасный кольцевой буфер `ResourceHistoryTracker` на 600 замеров (10 минут) в оперативной памяти бэкенда для отслеживания динамики нагрузки CPU, RAM и Network.
  - Модуль 5.6: Менеджер фоновых задач `DiskManager` с генерацией `task_id`, опрос статуса через IPC без блокировки пользовательского интерфейса, выбор стандартных папок Windows (`QuickDirectory`).
- Десктопная оболочка Tauri 2 (`src-tauri`):
  - Модуль `disk_commands.rs`: IPC-команды `get_quick_directories`, `start_disk_analysis`, `get_disk_analysis_progress`, `get_disk_analysis_report`, `start_duplicate_scan`, `get_duplicate_scan_progress`, `get_duplicate_report`, `cancel_disk_task`, `get_resource_history`.
  - Регистрация разрешений в `build.rs` и `capabilities/default.json`.
  - Фоновый цикл сбора метрик передаёт замеры в `history.record_snapshot`.
- React-интерфейс (`src/pages/DiskPage.tsx`):
  - Полноценная страница в тёмном стиле Studio Pearl с тремя режимами: «Карта и объекты», «Поиск дубликатов», «История (10 мин)».
  - Адаптивная полоса спектра распределения по категориям файлов и сетка легенды.
  - Списки крупнейших файлов и папок с полными путями и процентной долей.
  - Список групп доказанных дубликатов с подсчётом перерасхода места, полными хешами SHA-256 и путями к файлам.
  - Интерактивные SVG-графики трендов CPU, RAM и сети за 10 минут с расчётом минимума, среднего и максимума.
- Внедрён протокол изолированной параллельной разработки `isolated-development` (`.agents/skills/isolated-development/SKILL.md` и правило 12 в `AGENTS.md`).

### 2026-10-14 — v0.0.3 (Этап 3: Анализатор очистки)

- Создан крейт `cleaner-cleanup`:
  - Модуль 3.1: Каталог правил `RuleCatalog` с правилом категории `user-temp-v1` («Временные файлы пользователя %LOCALAPPDATA%\\Temp»). Оценка риска `Low`, фильтр возраста от 7 суток.
  - Модуль 3.2: Защита путей `path_safety`: валидация корней, проверка нахождения внутри разрешённой папки Temp пользователя, детектирование и пропуск `FILE_ATTRIBUTE_REPARSE_POINT` (0x400) и symlinks, строгий запрет корней дисков и системных папок (`\Windows`, `\System32`, `\Program Files`).
  - Модуль 3.3: Потоковый безопасный сканер `scanner` с обходом `ScanContext`: поддержка отмены через `AtomicBool`, ограничение глубины обхода (8), лимит файлов (50 000), фильтрация возраста (>= 7 суток) и сбор точных размеров в байтах.
  - Модуль 3.4: Менеджер фоновых задач `TaskManager`: регистрация `task_id`, отслеживание прогресса `TaskStatus` (`processed_items`), поддержка отмены в любой момент.
  - Модуль 3.5: Предварительный просмотр `CleanupCandidate` и `CleanupPreviewPage`: причины включения, относительный и абсолютный пути, размер, время модификации UTC.
  - Модуль 3.6: Хранение снимка результатов в памяти `StoredPreview`, порционная выдача кандидатов порциями по страницам (пагинация по 15 записей) без блокировки пользовательского интерфейса.
- Десктопная оболочка Tauri 2 (`src-tauri`):
  - Интегрирован `TaskManager` в `AppState`.
  - Зарегистрированы IPC-команды `start_cleanup_scan`, `get_scan_progress`, `cancel_cleanup_scan`, `get_cleanup_preview`.
  - Обновлены разрешения `capabilities/default.json` и `build.rs`.
- React-интерфейс (`src/pages/CleanupPage.tsx`):
  - Запуск сканирования, кнопка безопасной отмены в процессе анализа, живой счётчик обработанных файлов.
  - Постраничная таблица результатов с мгновенным локальным фильтром по имени и пути.
  - Сводка кандидатов: количество объектов и общий объём.
  - Строгая гарантия безопасности Этапа 3: **кнопка удаления отсутствует**, файлы на диске не изменяются (read-only analyzer).

### 2026-10-14 — v0.0.2 (Этап 2: Полезный монитор)

- Создан крейт `cleaner-system`:
  - Модуль 2.1: Адаптер `SystemCollector` на базе `sysinfo 0.33.1` для CPU и RAM. Первый замер CPU честно возвращает `FieldValue::NotMeasured`, предотвращая отображение фиктивных нулей до расчёта дельты.
  - Модуль 2.2: Мониторинг процессов `collect_processes` с PID, именем, нормализованным CPU (приведённым к шкале 0..100% делением на количество логических ядер), RSS памятью и безопасным чтением пути. Для системных процессов с ограничениями Windows возвращается статус `FieldValue::AccessDenied`. Команды завершения процессов исключены из соображений безопасности.
  - Модуль 2.3: Опрос локальных накопителей (диски), ограниченный частотой вызова не чаще одного раза в 30 секунд.
  - Модуль 2.4: Счётчики сетевых интерфейсов, расчёт скорости приёма/передачи (байт/с) через монотонные часы `Instant`, обработка сброса счётчиков ОС через `saturating_sub`.
- Создан крейт `cleaner-storage`:
  - Модуль 2.6: Менеджер локальной базы данных SQLite `StorageManager` (`rusqlite 0.32.1 bundled`) в каталоге `%LOCALAPPDATA%\CleanCore\cleancore.db` (с безопасным fallback на in-memory). Сохранение и валидация интервалов опроса (500..60000 мс).
- Обновлена десктопная оболочка Tauri 2 (`src-tauri`):
  - Модуль 2.5: Неблокирующий фоновый поток мониторинга с периодической отправкой событий `metrics-update` в окно, поддержка паузы и защита от наложения запросов через `try_lock()`.
  - Зарегистрированы команды IPC: `get_metric_snapshot`, `get_process_list`, `get_app_settings`, `save_refresh_interval`, `toggle_pause_metrics`.
- Обновлен React-интерфейс:
  - Живое обновление карточек CPU, RAM, Диск, Сеть на экране «Обзор».
  - Динамический SVG-график активности `ActivityChart` в стиле Studio Pearl для CPU, RAM и Сети.
  - Полноценная таблица `ProcessesPage` с живым поиском по названию, PID и пути, сортировкой по колонкам и бейджами ограниченного доступа Windows.
  - Сохранение интервала обновления (2, 5, 10 сек) в SQLite на экране «Настройки».
  - Поддержка паузы в шапке окна.
- Успешно пройдены все тесты: `cargo test` (15 тестов: 7 core, 3 storage, 5 system), `vitest` (5 тестов), `cargo clippy` (0 warnings), `cargo fmt`, `tsc`, production build и сборка бинарного файла `cleancore.exe` (15.6 МБ).
