# CleanCore — инструкции для Codex

## Главный источник требований
Перед работой прочитай `TECHNICAL_SPEC.md`. Если требования конфликтуют с безопасностью или существующей архитектурой, объясни конфликт и предложи безопасный вариант.

## Навигация и продолжение работы
1. Прочитай `AGENTS.md` и `TECHNICAL_SPEC.md`.
2. Прочитай `docs/ROADMAP.md`, `docs/TASKS.md` и `docs/STATUS.md`.
3. Перед реализацией модуля изучи соответствующие архитектуру, API, безопасность и проверки в `docs/`.
4. Работай в границах текущего запроса пользователя. Дорожная карта и раздел «Первый запрос» не являются заданием автоматически реализовать весь проект.
5. Этапы и границы безопасности определяет ТЗ; актуальную подробную последовательность и идентификаторы модулей уточняет ROADMAP. Исторические номера этапов и недель исходного ТЗ не смешивай с ID новой дорожной карты.
6. ROADMAP хранит план, TASKS — отметки выполнения, STATUS — краткий контекст, CHANGELOG — фактическую историю. Не объявляй запланированные возможности реализованными.
7. После модуля обнови TASKS и STATUS, при необходимости CHANGELOG. Используй шаблоны задачи, отчёта и решения из `docs/templates/`.
8. Перед заимствованием кода прочитай `docs/REUSE.md`: зафиксируй ревизию, лицензии конкретных файлов, изменения и проверки.

## Контекст
- Бесплатный open-source Windows-клинер/монитор, цель — Windows 10 x64.
- Backend: Rust stable + Tauri 2; frontend: React + TypeScript + Vite.
- Тёмная тема, первая локализация — русский.
- Local-first, без телеметрии и необязательных сетевых запросов.
- Очистка только по цепочке: scan → preview → явное подтверждение → повторная проверка → execute → локальный журнал.
- Собственный антивирус и автономные действия локального ИИ не входят в MVP.

## Правила
1. Работай маленькими этапами, не пытайся реализовать все модули сразу.
2. Сначала изучи структуру и сообщи план. Не перезаписывай файлы без необходимости.
3. Приоритет MVP: каркас, тёмный UI, чтение метрик и процессов, затем безопасный сценарий очистки пользовательских временных файлов.
4. Не запускай всё приложение от администратора. Не добавляй универсальное выполнение PowerShell/cmd и произвольный privileged helper.
5. Не удаляй файлы без явного подтверждения. Не удаляй дубликаты автоматически.
6. Защищайся от path traversal, junctions/reparse points, symlinks, смены объекта между сканированием и исполнением, Access Denied и занятых файлов. При сомнении безопасно пропускай объект.
7. Не выдумывай метрики. Если данные недоступны, показывай «нет данных».
8. Не добавляй телеметрию, облачные функции или сетевые запросы без явного требования.
9. Используй типизированные ошибки, узкие интерфейсы и тестируемые модули. Не делай микросервисы.
10. Запускай доступные проверки: `cargo fmt --check`, `cargo clippy`, `cargo test`, frontend lint/test/build. Не утверждай, что тесты прошли, если не запускал их.
11. После каждого этапа сообщай, что изменено, какие проверки выполнены, что осталось и какие риски есть.
12. ПАРАЛЛЕЛЬНАЯ ИЗОЛИРОВАННАЯ РАЗРАБОТКА (скилл `isolated-development`): Проект ведётся параллельно в двух нейросетях. Любой агент обязан строго соблюдать протокол изоляции: работать исключительно в границах назначенной задачи (для данной сессии — Этап 5: крейт cleaner-disk, DiskPage.tsx, disk_commands.rs). Запрещено модифицировать, рефакторить, форматировать или откатывать (git restore / checkout / reset) файлы параллельных этапов (cleaner-cleanup, cleaner-execution, cleaner-system, cleaner-storage, CleanupPage). Проверки запускать таргетированно.

## Первый запрос
Прочитай `TECHNICAL_SPEC.md`, проверь окружение и текущую структуру. Затем создай минимальный каркас MVP: структуру проекта, документацию, базовый тёмный UI и безопасные команды чтения системных метрик. Пока не реализуй удаление файлов и административные действия.
