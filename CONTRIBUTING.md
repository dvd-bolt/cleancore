# Работа над CleanCore

## Порядок работы

1. Прочитайте [AGENTS.md](AGENTS.md), [ТЗ](TECHNICAL_SPEC.md), [план](docs/ROADMAP.md) и [статус](docs/STATUS.md).
2. Выберите одну разрешённую текущим запросом задачу из [чек-листа](docs/TASKS.md). Убедитесь, что её зависимости выполнены.
3. Опишите цель и приёмку по [шаблону задачи](docs/templates/TASK.md).
4. Реализуйте минимальный законченный результат. Не добавляйте будущие модули заодно.
5. Выполните применимые [проверки](docs/TESTING.md), обновите документацию и статус.
6. Подготовьте коммит и [отчёт](docs/templates/REPORT.md) с реальными результатами.

Подготовлен комплект документов, создан локальный Git и публичный репозиторий https://github.com/dvd-bolt/cleancore. Приложение создаётся отдельными задачами.

## Ветки и коммиты после создания Git

- Основная ветка — `main`; ветки задач — `feat/<id>-<описание>`, `fix/<id>-<описание>` или `docs/<описание>`.
- Сообщения коммитов: `feat: ...`, `fix: ...`, `docs: ...`, `test: ...`, `chore: ...`.
- Один коммит отражает логически связанное изменение; не смешивайте форматирование всего проекта с исправлением функции.
- Не коммитьте секреты, пользовательские журналы, локальные базы и результаты сборки.
- Теги продукта ставятся после приёмки этапа, не после одной задачи.

## Качество

Проверки Rust и frontend перечислены в [TESTING](docs/TESTING.md). Если манифестов нет, отметьте проверку как неприменимую. Не выдавайте отказ запуска за пройденный тест.

Документы пишутся по-русски; идентификаторы кода — по-английски. Форматирование задаёт `.editorconfig`. Версии и lock-файлы фиксируются после создания каркаса.

## Безопасность

Любое изменение с файловыми операциями сверяется с [моделью угроз](docs/THREAT_MODEL.md) и [правилами очистки](docs/CLEANUP_RULES.md). Не повышайте права автоматически. Для изменения архитектуры используйте [шаблон решения](docs/templates/DECISION.md).

## Сторонний код

Следуйте [REUSE](docs/REUSE.md). До копирования проверьте конкретные файлы, ревизию и зависимости. Сохраните авторство и лицензию; отдельно отметьте адаптацию. MIT-лицензия CleanCore не заменяет исходные лицензии компонентов.

## Сообщения об ошибках

Для обычной ошибки используйте шаблон GitHub issue после публикации репозитория. Не прикладывайте полные журналы с персональными путями и секретами. Правила сообщения об уязвимостях — в [SECURITY](docs/SECURITY.md).
